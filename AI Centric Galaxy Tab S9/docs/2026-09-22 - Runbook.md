- Termux has shared-storage read/write permission for selected public documents; System browsing excludes hidden, Android/private paths and symlinks. Termux and Galaxy Device Tools are exempted from battery optimization for the running local engine/helper; this can increase battery use.

### Update and recover this deployment

Run `./galaxy build`, `./galaxy test`, and `./galaxy android-build` on the workstation. The Android command has a ten-minute timeout and one Gradle worker. Install the two APKs with `adb install -r`; do not use `./galaxy android-install` for this local mode because that legacy command adds USB reverse forwarding. Transfer only `server`, `shared`, `scripts`, `dist`, `examples`, manifests and the launcher to the Termux runtime, preserving `.local/` and `node_modules/`. Dependency updates must be installed for Android in Termux; never copy workstation native Node binaries.

Stop/restart the local engine only after its active conversation is idle. Launch Galaxy to restart through its fixed intent. For manual recovery in Termux: `cd ~/galaxy-workspace && bash scripts/tablet-engine.sh`. For routine pairing use native **Home → Connection → Reconnect this tablet**. Manual developer fallback: `node scripts/pair.ts`. For Codex sign-in recovery, `CODEX_HOME="$PWD/.local/codex-home" bash scripts/tablet-codex.sh login --device-auth`. Never copy host Codex credentials as a shortcut.

Do not uninstall Termux: uninstalling it removes its app-private workspaces and credentials. Back up its data deliberately before reinstalling or replacing it. APK updates preserve app data with the same signing key. The repository contains source, not provisioned credentials or a public distributable bundle.

Tailscale is unnecessary for local mode. The temporary host Serve route was removed. USB debugging is for installation/inspection only; runtime tools do not invoke ADB. The temporary TCP debugging listener used during investigation was restored to USB-only; port 48441 is closed and the TCP property is 0.


## 0.4.0 continuity and document update

Before updating, back up code separately and use SQLite's online backup API for `.local/galaxy.sqlite`; retain the original `.local/` and account/Codex credentials. Check that no conversation is starting/running/waiting/stopping before stopping the engine. Update the APK with the same signing key and transfer code through tar stdin, excluding runtime state. Never restore a stale database merely to roll back code.

Startup adds the metadata/instance ID and recovery tables, and adds export receipt/history columns without deleting old rows. Prior export timestamps remain unknown rather than fabricated. Recovery holds sensitive unsent chat/report text in the private SQLite database and in the paired browser's localStorage fallback. It is not a backup or a cloud sync. Clearing Termux data removes its copies; clearing browser data alone can recover from the paired engine. Preserve both the DB and document directories for a complete backup. Never commit or log their contents.

Native local re-pairing uses `tablet-engine.sh --pair`, which invokes `scripts/tablet-pair.ts`. The short-lived ticket hash is private, expires after 60 seconds and is consumed once. Only localhost tablet mode accepts the native pairing endpoint; the ticket returns via an unexported PendingIntent receiver. No arbitrary command arguments, browser bridge, URL token or clipboard credential is introduced. Startup waits for a healthy local engine before WebView navigation; browser session checks retry only reads.

XLSX/PPTX text extraction uses bounded standard-library Python ZIP/XML, no Office automation or remote resource access. Keep `server/office-text.py` with the deployment. Downloads preserve source bytes; Office applications receive temporary read grants for copies. Report export receipts preserve creation/version, chosen cloud destination and confirmed native save filename. Android file-provider synchronization may continue after a local stream closes; receipts are not proof of cloud arrival.

Rollback: preserve the current DB and drafts, reinstall the previous APK if needed, and restore only the backed-up code. Additive columns/tables need no destructive downgrade. Re-test pairing, source opening and draft recovery before release. A force-stop test must wait for **recovery saved** before killing the app. Never test with unsaved real user work or an active AI turn.

## Microsoft sign-in provisioning (developer only)

Register **Galaxy Workspace** once in an owner-controlled Microsoft tenant. End users never enter an application ID. The reviewed Graph creation payload is `config/microsoft-registration.json`: personal and organizational accounts, public-client device flow, token version 2, and delegated `User.Read` / `Files.ReadWrite`. It requests no client secret, application permissions, directory-management access, or tenant-wide consent. The underlying file permission is broader than this app's supported save operations.

Use the Microsoft Entra portal as the authorized developer, or the [Graph application API](https://learn.microsoft.com/en-us/graph/api/application-post-applications?view=graph-rest-1.0) with an appropriately authorized operator. Do not borrow a third-party application's identity, broaden the existing CLI login's permissions, or silently alter an existing registration. Verify the selected owner tenant before creating anything. If an app with this purpose already exists, verify its ownership and settings before reuse.

Portal equivalent: **App registrations → New registration**, name **Galaxy Workspace**, select accounts in any organizational directory **and personal Microsoft accounts**. Under Authentication, enable **Allow public client flows**. Add the two delegated Microsoft Graph permissions. This device-code flow needs no redirect URI. See [Microsoft registration guidance](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app), [device flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code), and [permission identifiers](https://learn.microsoft.com/en-us/graph/permissions-reference).

The developer then runs `./galaxy configure-microsoft APP_ID` on the host using the newly verified registration's client ID. This is an identifier, not a password. The command writes private host settings, preserves the existing linked connection, rejects active/orphaned sign-in states, and refuses to replace a previously configured registration. Repeating it with the same ID is harmless. There is no tablet API for changing this configuration. Replacing an established registration requires an explicit host migration; do not overwrite account caches in place.

Refresh Connections, or tap **Check sign-in availability**. When ready, each user chooses **Sign in with Microsoft**, enters the temporary code on Microsoft's page, and signs in normally. Verify each of the three actual identities and tenant-consent behavior before claiming all accounts are connected.

## Start, pair, stop

Run `./galaxy start` from the project folder. The service listens on `127.0.0.1:4318`. It does not start Codex until a message is submitted. Get the pairing code using `./galaxy pair` locally. Stop the service with Ctrl+C or SIGTERM; it stops its active worker before closing storage.

`./galaxy pair --rotate` revokes paired browser sessions and replaces the pairing code. Cookies expire after seven days. Event streams reopen regularly to recheck authentication.

The default origin is exactly `http://localhost:4318`; `http://127.0.0.1:4318` is intentionally rejected as a different Host. `GALAXY_ORIGIN` must match the browser origin. `GALAXY_PORT` changes the local listener port; `GALAXY_STATE_DIR` chooses a private state directory. The listener remains loopback even if the public origin is HTTPS.

## Tablet

First test: USB debugging authorized on the intended tablet, then `adb -s SERIAL reverse tcp:4318 tcp:4318`. Open `http://localhost:4318` in the tablet browser. Verify screen lock and reconnect. Remove that one reverse mapping when done. Do not run device wiping, flashing, bootloader, recovery, or appliance migration scripts from the parent repository.

Daily use: configure a Tailscale **Serve** HTTPS reverse proxy only after inspecting existing Serve configuration. Preserve other services. Set `GALAXY_ORIGIN` to that exact private HTTPS origin before starting the host. The proxy must forward the original Host header. Application pairing remains required. Do not enable Funnel or expose the port to the public internet. Tailscale access alone does not replace application authentication.

The host must be awake and online. Offline tablet use shows the cached shell and reconnection state; it does not execute work locally or queue new requests silently.

## Recovery

- Browser disconnect: reopen the saved conversation URL or select its history entry. The existing worker continues for the remainder of its ten-minute deadline. Events replay from the last cursor.
- Service restart: active conversations become interrupted, with a visible recovery event. The app never restarts a pending request automatically. Inspect draft changes and command evidence before continuing.
- Uncertain submission: a reused message ID returns the recorded state. Do not manually resend the same intended operation until its outcome is understood.
- Source conflict: keep the draft; inspect the newer original. The app refuses the save. Import a new OneDrive collection if the cloud source changed.
- Expired Microsoft sign-in: reconnect that account. Existing imported files remain available on the host. Changing to a different Microsoft identity cannot save old imported sources.
- Codex version mismatch: don't bypass the check. Regenerate app-server schemas, review protocol changes, update the expected version and rerun integration and live acceptance checks.
- Worker fails: inspect Activity & evidence, including command exit codes. Raw worker stderr is not exposed to the browser. No fallback to full-access execution is automatic.

## State and backups

All runtime state is in `.local/`, mode 0700. Sensitive files use mode 0600. It includes the SQLite database/WAL, pairing code, encrypted Microsoft caches, cache encryption key, imported documents, and draft directories. These must not be committed or synchronized indiscriminately.

Back up the state directory only when the service is stopped, into an appropriately protected location. A copied token-cache key with its ciphertext can decrypt it; the local encryption is not a separate trust boundary. The project does not yet offer automated retention, so review disk use periodically. Never delete a draft or collection that is needed for an unresolved conversation.

Draft metadata is stored beside the draft directory. Its internal `.git` is a comparison baseline, not the original project's history. Changes saved to originals are retained as review events. Source Git repositories are not committed or pushed by the application.

## Report workflow operations

The host needs `python3`, `pandoc` and `libreoffice` on PATH in addition to the existing preview dependencies. Reports are Markdown/text in separate drafts. Prepared exports live under private `.local/exports/`; SQLite maps their opaque IDs to a conversation and content hash. Download requires the paired session. No background cloud upload is scheduled. A pending cloud export becomes uncertain on restart, and the same export ID cannot submit a second upload. Inspect the selected destination before creating a new export after an unconfirmed result.

Successful import request IDs and fingerprints are retained in `material_batches`. Uploads stage under `.local/staging/` and publish as uniquely named source batches. A failed pre-publication operation removes its staging directory. A rare filesystem/Git/database failure after publication deliberately retains recoverable copies; inspect the destination and current draft before reimporting. Other existing drafts do not automatically receive new material. Review state/export disk usage periodically; there is no automated retention policy.

Independent tablet clients use APK 0.4.0 for Open/Save/Share and local re-pairing. Update with `adb install -r`; no USB reverse mapping is used. The legacy `android-install` path applies only to optional workstation mode.

## Tablet System connection and recovery

Link the intended authorized Galaxy Tab S9 Plus from the host with `./galaxy bind-tablet ADB_SERIAL`. The script checks the model and writes ignored `.local/tablet.json`; it does not change OneDrive settings, grants or Android permissions. There is no browser endpoint for rebinding. The current physical tablet is already linked. Keep its normal USB reverse mapping for the app connection. System diagnostics and settings use host-to-device ADB separately.

System appears permanently at startup. If the tablet is disconnected or unauthorized, the app explains how to reconnect; it never chooses another attached device automatically. Do not replace the binding to rescue an old proposal. Rebinding invalidates proposals for the previous serial.

For a failed setting change, inspect the receipt and Android's current value. Pending writes interrupted by service restart become uncertain; there is no automatic retry. A stale before-value or expired proposal requires a fresh proposal. Undo is conditional and must not overwrite a value changed elsewhere. Keep the action records for evidence. Normal temporary document previews are removed on completion; crash leftovers in `.local/tablet-previews/` are private read copies, never device originals.

## Outlook Assistant reader

`./galaxy android-build` builds and checks both the existing Galaxy shell and the separate reader APK. `./galaxy android-install SERIAL` installs both, preserving the main app's data, then opens Galaxy. The reader is `android/reader/build/outputs/apk/debug/reader-debug.apk`, package `com.adamgoodwin.galaxyreader`. Existing devices need only `adb -s SERIAL install -r android/reader/build/outputs/apk/debug/reader-debug.apk` when the main shell has not changed. It has no launcher activity or account sign-in. It is invoked transiently by the host via ADB instrumentation and holds no mailbox tokens.

The host driver takes structured JSON on stdin and emits structured JSON. Never add user-controlled activities, shell commands, coordinates, external links, sending or invitation controls. Validate the intended device with the existing tablet binding before invoking it. If a read fails, inspect its saved error and Outlook's visible state; do not reuse a previous dump or silently repeat a whole model request. Authentication remains in Outlook. No Microsoft permission grant or existing OneDrive account configuration is changed by this reader.

Meeting sources and briefs are in ignored `.local/meetings/`; SQLite stores the conversation, registered meeting folder and source activity. Exporting to OneDrive remains a separate user-selected new-file action. Source snapshots are sensitive local documents; keep `.local` private and out of Git. The helper writes no device-side capture files. Tests use synthetic XML and an injected UI runner; only explicit live checks touch the actual tablet.

On the tested Outlook version, keep search on **All** results: Mail-only search renders message rows without accessible text. Enter alone can leave a suggestion; the driver selects only the exact `Search for` suggestion after selecting the result filter. Do not treat a suggestion or blank accessibility rows as an empty mailbox. Collapsed messages expose typed references for their header or **Open full message**, and scrolling prioritizes the open conversation over the search list. Recheck these control identifiers after an Outlook update.
